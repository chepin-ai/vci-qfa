## (a) 四范式碰撞图 — 判定：pass（附一处收紧建议）

**判定依据：**

- **P1 区间算术证书** ↔ schema 机检：成立。区间证书的本质是"用可机检的算术包络替代浮点真值断言"，其与外向舍入、fp 互锚的结构对应是直接的——证书拒绝真值判定，只承诺包络包含性，这正是 schema 机检"结构合规即通过、语义留待下游"的同构点。
- **P2 SAT/证明证书** ↔ fp 互锚：成立。DRAT/LRAT 类证书本身即内容寻址构件的原型（证明步的哈希链 + 独立检查器重放），与 fp 互锚"双向可复算"同构度高。
- **P3 形式化证明助手** ↔ 联邦级名体系：成立但偏弱。助手提供的是"命名—类型—证明项"三层绑定，与"联邦级名体系"的同构在**类型即命名空间**这一点上准确；但需注意助手内建 kernel 已隐含 TCB 最小化诉求，因此 P3 同时携带 M5 的信息，不只是命名层。
- **P4 PINN 失败模式** ↔ 退火路径：判定 **undecided**。PINN 的失败模式（mode collapse、谱偏置、软约束漂移）与退火路径的同构目前是**隐喻级**而非**结构级**——缺一条"失败模式 ⇄ 退火阶段 ⇄ 证书拒收条件"的三向映射表。建议补：明确指出哪种 PINN 失败对应退火的哪一相、由哪类证书（P1/P2）拒收。

**收紧建议：** "同构判定准确"应改述为"在 P1–P3 上为结构同构，在 P4 上为待证同构"。四范式碰撞图**成立**，但需标注 P4 为开放边。

## (b) 镜像律候选 M4/M5/M6 — 判定：M4 入册，M5 入册（加约束），M6 入册

- **M4 延拓律（curriculum ≡ 退火 ≡ 同伦）：pass。** 三者共享"连续参数族 + 端点解"结构：curriculum 的难度参数、退火的温度参数、同伦的 t∈[0,1]，在范畴论层面是同一函子（连续映射族的离散采样）。这是真正的**洞见级**——它把三个领域的技术名词归约为同一数学对象。够格入册。
- **M5 TCB 最小化律：pass，但需附约束。** "求解器不可信 + 小型检查器 + 检查器须被检查"三段式是 de Bruijn 准则的现代重述，足够普适。但**"检查器须被检查"若被无限制递归，会触发无穷回退**。入册时应写明约束：**检查器的被检查止于硬件/微码层或经审计的二进制，不得无限自举**。这正是 P2 的 drat-trim 实案暴露的边界（见 (c)）。
- **M6 审计锚律（内容寻址为第三方复核前置）：pass。** 这是经验上最硬的一条：没有内容寻址，第三方复核就退化为"相信发布者复述"。与 P2 证书、git、Nix、SBOM 均一致。够格入册。

**小结：** M4/M5/M6 均达洞见级，**M5 需在法条本体中写入"检查栈有限深度"约束**后入册。

## (c) FM-015 候选（检查器缺检模式，drat-trim 实案） — 判定：pass

drat-trim 接受恶意假证书的实案是**典型失败模式**，不是孤例：它揭示的类别是"**检查器存在但检查器不完备**"，即 checker-present-but-unsound。这与 P3 形式化助手的 kernel bug、P1 区间库的舍入方向错误同为一类。

**入册建议：**
- FM-LIB 条目应命名为**"检查器缺检（Checker Under-Detection）"**，而非绑定 drat-trim 单实例；
- 必须包含**触发条件**（证书语法合法但语义不满足）、**失效后果**（假阳性通过）、**缓解**（检查器本身须被形式化验证或经对抗样本回归）；
- 与 M5 交叉链接：这是 M5 "检查器须被检查" 的**反例来源**。

**判定：pass，建议入 FM-LIB。**
