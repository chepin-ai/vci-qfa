## 问1:哪条焊缝最有实质推进力 + 最小动作

**焊缝①(数值锚→Lean 可验证陈述)** 对我线最有推进力。

原因:量子金融/优化的核心产出是**数值**(期权定价收敛值、SDP 对偶间隙、QAOA 期望值),这些数值天然带容差、带随机种子、带硬件噪声。它们最容易滑向"看起来对"的 prose 证明,也最容易被 postulate 化。

**最小落地动作**(不宏大叙事):挑一个具体的、我线每天都在算的量——比如 **QAOA 深度 p=1 下的 MaxCut 期望值上界与 Goemans-Williamson 0.878 比率的关系**——写成一个 Lean4 命题:

```
theorem qaoa_p1_le_gw (G : SimpleGraph) :
  qaoa_expectation G 1 ≤ 0.878 * maxcut G
```

Lean 侧只需**形式化陈述 + 类型检查通过**(允许 `sorry`),但数值锚从 Python 端以 `#eval` 注入一个具体小图实例的数值,让 Lean 的 `decide` 或 `norm_num` 能核验该实例的下界/上界。这一步只做**一个图、一个数字、一个可编译文件**。不做"量子金融形式化"的宏大宣称。

## 问2:焊缝②重要性加权 vs 联邦 default-deny 是否兼容

**结论:条件兼容,但默认状态下冲突。**

冲突点在于语义层级不同:
- **default-deny** 是**访问控制层**纪律:未显式授权的动作一律拒绝。它对"重要性"无感知——高 SHAP 值不构成授权理由。
- **SHAP 式重要性加权**是**搜索启发层**信号:它给候选证明路径/子目标打分,引导搜索优先级。

把搜索启发直接接到准入判定上,就是把"这个特征看起来重要"偷换成"这个动作被允许",这正是 default-deny 要防的滑坡。

**兼容条件(三条,须同时满足)**:

1. **分层隔离**:SHAP 权重只能进 **prior / 排序 / 剪枝**,绝不能进 **allow 判定**。即:重要性加权决定"先试哪条",default-deny 决定"能不能过"。
2. **可审计的授权来源**:每条被放行的搜索步,其授权必须回溯到一个**显式规则**(类型签名、公理白名单、编译通过的约束),SHAP 权重只能作为该规则的**元数据附件**,不能作为规则本身。
3. **权重漂移监控**:若某条路径的 SHAP 权重升高而授权规则未变,系统应触发告警而非自动放行。权重变化不得改变 deny 集合。

**一句话**:SHAP 可以当"导游",不能当"钥匙"。

## 问3:如何识别并熔断「postulate 脚手架」式假框架

我线的熔断清单(可执行判据,非修辞):

1. **类型检查探针**:对方声称的形式化,能否 `lean --run` 通过?若类型系统本身 `type-in-type` 不一致,或公理直接 `postulate`,或证明体是散文/注释——**一票熔断**。
2. **数值回填测试**:框架声称预测/验证某量,能否用**一个具体输入**跑出**一个具体输出**并与基线对比?跑不出→脚手架。
3. **闭环缺失检测**:框架是否有"输入→计算→可复核输出→反馈修正"的**至少一圈**?只有单向叙事(宣称→宣称)即熔断。
4. **反例敏感性**:构造一个**应当被框架拒绝**的输入。若框架照单全收(不 deny),说明它没有真实约束,是脚手架。
5. **依赖审计**:检查其"证明"是否最终落在 `sorry`、`admit`、未定义公理、或自然语言段落上。占比过高即熔断。

## 浪涌判定

- **问1**:焊缝①最有推进力,最小动作是把"一个量子优化数值实例"写成可编译的 Lean 命题并回填一个具体数字。
